### A.3 Reference values, in plain English

Each metric starts as a raw measurement in pixels or degrees. To put it on 0–1, it is divided by a reference value, which is the point where the score hits 0 (or where a term maxes out). Anything past that is clipped. **All of these were picked by judgement. None comes from a source or from data.**

| Metric | Raw measurement | Reference value | What it means |
|---|---|---|---|
| b | SD of line angles, σθ | 15° | Lines tilting with an SD of 15° or more score 0. These pages measured 0.4–0.9°, so they used only the top 6% of the scale. |
| s | Variance of spacing between line bands | H²/16 = 245,025 px² | Equivalent to a spacing SD of a quarter of the page height (495 px). Measured SDs were 24–26 px, about 20× smaller, so every page scores ≈ 0.997. |
| f: density D | components per ink pixel | × 40, capped at 1 | D = 1 only if the average component is 40 px or smaller. Average page measured 0.018. |
| f: dispersion N | mean nearest-neighbor distance | √(page area) = 1697 px | Average page measured 56.6 px → N = 0.033. |
| f: small ratio R | share of components < 150 px | none needed | Already a proportion. Average page measured 0.73. |
| Table I bands | – | 0.80 / 0.50 | Judgement cut-offs. |

This answers Breen's normalization question (comment 24): we do not know the true maximum. The references are chosen ceilings, and they are much looser than real handwriting, which is why all three pages cluster near the top. The fix is to calibrate them on a larger page set (e.g., reference = 95th percentile of observed values) or tie them to the page itself (e.g., spacing SD ÷ mean spacing).

### A.4 Fragmentation formula: were the terms flipped?

**Yes, the code flips them.** `document_readability.py:530–536` computes

```
fragmentation = 0.45*D + 0.35*N + 0.20*R
f = 1 - fragmentation
```

D, N and R all rise with fragmentation, and the whole sum is inverted. Because the weights add up to 1.00, this is mathematically identical to flipping each term on its own. So the messy page coming out "least fragmented" is **not** a sign error.

**The paper's formula is wrong as written**, because it leaves out the "1 −". It now reads `f = 1 − (0.45D + 0.35N + 0.20R)`.

What actually drives the result (measured on the average page):

| Term | Scaled value | × weight | Share of index |
|---|---|---|---|
| D | 0.018 | 0.008 | 5% |
| N | 0.033 | 0.012 | 7% |
| R | 0.727 | 0.145 | **88%** |
| Index | | 0.165 | f = 0.835 |

D and N barely register because of their reference values (A.3), so in practice f is about 1 − 0.2 × R. All three notebooks are on printed grid paper. In the thresholded image (Fig. 3, panel b) the faint grid turns into short white dashes, and those dashes are most of the "small components". The messy notebook has a much darker grid and a hand-drawn table, which survive as long connected lines, so it has fewer small pieces and a higher f. f is largely measuring how visible the printed grid is.

### A.6 Fig. 3

The panels were matched to the five images the code saves (`save_preprocessed_images`):

| Position now | Panel | Code output |
|---|---|---|
| Top left | Adaptive threshold (inverted) + opening | `_binary.png` |
| Top middle | Morphological closing | `_closed.png` |
| Top right | Connected components (colored) | `_components.png` |
| Bottom middle | Canny edge map | `_edges.png` |
| Bottom right | Grayscale | `_gray.png` |

- **Why white on black:** adaptive thresholding uses `THRESH_BINARY_INV`, which makes ink white (255) and paper black (0). OpenCV's morphology, connected-component and projection steps treat nonzero pixels as the foreground, so the ink has to be white. The grayscale panel is the only one that isn't inverted. The draft reply (16R15) says the inversion happens during grayscale conversion; that is incorrect.
- **"Thresholding 1 & 2":** there is only one thresholding step. The two panels that look like thresholding are (1) the threshold + opening output and (2) a Canny edge map drawn from it. The edge map is computed but **no metric uses it**, so it can be labelled "for illustration only" or dropped.
- **"Right to left" is wrong.** All four arrows point right, and the grayscale input sits last (bottom right), so neither direction reads in processing order. I recommend reordering the panels: (a) grayscale → (b) threshold + opening → (c) edges → (d) closing → (e) components. The caption with one line per panel is in `revised_text.tex`.

### A.7 Spatial organization barely moved (0.997 to 0.998)

It is the same reference-value problem as A.3, plus the grid. The reference SD is 495 px against measured 24–26 px, so s cannot drop much below 1 on any realistic page. The projection profile also picks up the printed grid rows (64 "bands" about 30 px apart on the average page), so every page shows similar spacing. A short paragraph is in the Discussion of `revised_text.tex`. Note that s actually ranks messy as the best-organized page, which is consistent with the grid explanation.
